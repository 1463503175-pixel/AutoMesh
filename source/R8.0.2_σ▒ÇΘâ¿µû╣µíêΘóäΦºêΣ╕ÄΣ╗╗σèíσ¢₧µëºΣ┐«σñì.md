# AutoMesh R8.0.2：局部方案预览与任务回执修复

## 本次针对的实机问题

R8.0.1 在部分 ANSYS Mechanical 2024 R2 / IronPython ACT 会话中，终态回执仍出现 `('unknown', '\x00', 0, 1, '')`。任务可能已经进入 ACT 终态，但 `job_<id>.json` 与 `last_result.json` 未成功落盘，AutoMesh 因而无法确认「生成局部方案」的结果。

## 修复内容

1. **回执文件替换**：不再依赖 IronPython 对 `System.IO.File.Replace/Move` 的重载绑定。Windows 优先使用 Unicode `MoveFileExW`（替换现有文件 + 写入完成）；不可用时使用同目录可恢复 rename，并保留详细错误原因。
2. **预览结果绑定 Job ID**：`warning_refinement_plan.json` 增加 `job_id`。只有方案文件的 Job ID、工程路径和几何指纹均与当前任务一致，才允许恢复预览成功；旧方案不能冒充本次结果。
3. **运行中终态恢复**：Go 端在当前任务轮询期间检查本任务的终态回执标记。ACT 已结束但 JSON 回执丢失时，若存在同 Job ID 且通过校验的局部方案，则恢复为真实预览结果；否则只恢复为 error，不伪造成功。任务锁仍由当前 taskRun 在收到终态后释放。
4. **预览阶段进度**：增加标记组核验、单元几何提取、现有 Sizing 检查、空间分簇和方案保存等阶段提示。
5. **R8.0.1 原位升级白名单**：登记并核验 R8.0.1 官方 Worker 与警告区脚本哈希，允许安全替换为本版；未知/人工修改脚本仍拒绝覆盖。
6. **跨工程历史清单隔离**：Data 目录中的旧 QR 发布清单若属于其他工程，且当前模型树已不存在任何 AutoMesh_QR Sizing，则不再阻断新模型的预览/发布；若当前模型仍有保留的 QR 控件，则继续拒绝猜测归属。
7. **安全边界不变**：生成局部方案仍是只读分析，不会在 Mesh 中创建 Sizing，也不会生成/清除网格。只有人工审核后点击「审核发布 Sizing」才创建局部控制；之后是否重划仍由用户在 Meshing 中单独确认。

- Python 回归：213 项通过。
- Go 回归：全部通过，新增覆盖“同 Job ID 方案可恢复”和“其他 Job ID 方案必须拒绝”。
- Windows x64：完成交叉编译。

## 建议验收顺序

1. 保留当前已生成网格，不清网格、不重启 Workbench、不操作 Fluent。
2. 关闭 AutoMesh 界面后，运行本版；确认标题显示 R8.0.2。
3. 先执行偏度区间标记，再做当前工程只读扫描。
4. 点击「生成局部方案」，等待界面明确显示完成；此步骤 Mesh 树不应变化。
5. 打开方案报告，核对警告单元数、覆盖数、候选组数和拒绝原因。
6. 只有方案与当前模型匹配且候选有意义时，再逐项人工审核；暂不直接发布全部候选。

若仍失败，请保留并提供 `job_receipt_write_error_<本次JobID>.txt`、`job_progress_<本次JobID>.json` 和 `warning_refinement_plan.json`，不要重复投递同一任务。
