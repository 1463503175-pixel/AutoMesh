# AutoMesh R7.9：目标完成度、源码核查及前端第二轮修复

**唯一基线：** 用户实际上传、已校验的 `AutoMesh_R7_8_UI_Workflow_Integrated.zip`。本版保持 7 个 ANSYS `assets` 文件与 R7.8 按字节完全一致，只修改 Go/Win32 界面状态、局部数字验证及键盘交互。**未触碰 ANSYS 工程、网格、Sizing、任务锁或 Fluent**。

## R7.9 确认修正的问题

1. **高偏度标记状态假阳性**：R7.8 仅检查 `warning_refinement_marker.json` 文件存在。R7.9 检查 JSON 有效、状态、当前工程、几何指纹、网格单元数、组名、Object ID、元素 ID 唯一且数量与工作表一致。拒绝过时或损坏记录。
2. **旧方案按钮仍可点**：查看范围仅在当前快照拥有有效预览回执和报告时可用；`warningpublish` 仍需完整的已审核方案。不能依靠历史 HTML 文件冒充当前有效方案。
3. **一千万单元科学计数法**：R7.8 的部分标记身份核对把 `float64(10055480)` 显示成 `1.005548e+07` 后错误地解析为整数。本版使用安全的 `meshCellCount`，拒绝小数、负数和非法类型，不截断或四舍五入。
4. **无效偏度范围**：编辑上下限时，原生按钮立即变为不可用并在下方显示 `0 ≤ 下限 < 上限 ≤ 1`，避免先点后报错。
5. **键盘 Tab 导航**：Win32 消息循环加入 `IsDialogMessageW`，当 Tab 焦点进入可滚动区的控件时，自动调整横/纵滚动，使焦点尽量保持可见。仍需 Windows 实机检查控件创建顺序是否与视觉顺序完全一致。
6. **执行时输入仍可修改**：任务运行期间禁用系统选择、确认、端口、参考尺寸、导出路径、偏度区间，避免用户误以为编辑中的文字会改变已提交的任务。

- `go test ./...` 全部通过；新增 `ui_r79_regression_test.go` 覆盖实际 `10,055,480` 单元、旧工程/错网格身份、标记 JSON 损坏、偏度范围、Tab 滚动边界等。

- Windows x64 图形程序编译成功；独立解压后需再次验证 EXE 与源码构建产物 SHA-256 一致。
- 用户现场未运行 Windows/ANSYS；没有宣称已实现 125%、150% DPI 视觉验收、真实 Tab 键导航或 Meshing 运行测试。

## 实机验收顺序（只读优先）

1. 关闭旧 AutoMesh，保留已打开的 Workbench/Meshing，**不要重复提交仍未核实终态的任务**。
2. 在独立英文路径解压新版。先测试 1366×768、125%/150% 缩放及较小窗口。用 Tab/Shift+Tab 验证可聚焦、自动滚动且没有遮挡，确认键盘能正常输入组合框和文本框。
3. 未扫描时，生成方案/发布 Sizing 不应可点击；仅连接、任务状态和日志可用。输入无效偏度（例如 0.95～0.90）时，标记按钮应自动禁用，调整为 0.90～1.00 后恢复。
4. 当前 Mesh 执行只读扫描后，确认 297 个高偏度标记属于当前工程，相关按钮正常。更换工程或重新生成网格后必须重新扫描与标记，过期 marker 不得自动允许生成方案。
5. 运行只读质量检查和方案预览；本轮并未改变 6/24 候选发布逻辑，**不要将 UI 修复当作网格质量提升**。仅在实际审核作用域、片间净空后再批准发布。
6. 打开更多设置里的完整诊断日志，确认长错误未丢失。任何 UIA/焦点异常应通过只读检查工具记录，禁止使用截图坐标点击控制软件。

## 后续不足，不宜一次性强行实施

- 依然采用固定虚拟内容宽度+滚动，不是多断点自然重排；要完整支持 150% DPI 高分屏需要单独的布局引擎/视觉回归，不能仅修改一个 DPI 常量。
- 任务诊断需从记事本进一步发展为界面内可展开、可复制的状态记录；要有内置搜索/筛选、错误代码映射和可访问性验证。
- 仍未集成实时内存监控与网格真实变化收益评估；要保留 32 GiB 保护并严格分离“发布控制”和“重划网格”两个用户授权动作。
