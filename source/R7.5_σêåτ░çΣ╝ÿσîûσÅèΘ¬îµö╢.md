# AutoMesh R7.5 — 297 个高偏度单元分簇二次细化

## 本次直接修复

- **根因**：R7.4.1 在 `_read_warning_elements` 中以 `len(selected)>64` 为整个选区的一刀切限制，直接返回 `selection_exceeds_safe_hotspot_limit`，使 297 个单元始终生成 0 个影响域。
- **修复**：64 个单元保留为**每个候选局部影响域**的上限；单次 ACT 读取另设 1536 单元的硬限（主要防止 32 GB 电脑耗尽资源）。未取消安全限制。
- 逐元素读取真实节点坐标与几何 Body 归属；无法唯一映射时仅排除该元素并记录原因，不使全部候选失败。不能证明真实 Body 归属时拒绝猜测。
- 按几何 Body、共享网格边（至少两个角节点）或保守局部空间邻近构造缺陷连通簇，再把过大的连通簇分裂为有半径限制的局部簇。
- 每簇独立计算球心、球半径、建议尺寸；只接受半径 ≤12 mm、每簇 ≤64 单元、本轮 ≤6 个球形影响域、总局部体积/尺寸³ 代理量 ≤120000 的候选。超过单次预算的簇单独列出原因，不阻止其它安全簇。
- 对已有 Geometry Body/Face/Edge 作用域的 Sizing 进行尺寸检查；Face 按已扫描映射，无法识别的 Edge 必须通过 ACT 几何关联唯一映射才能通过。
- Sphere of Influence 绑定**真实几何 Body**，不会绑定临时 Mesh Elements Named Selection。复用同一方案的自建 Sizing；新方案若控制数目一致、归属/尺寸/半径/球心均可验证，优先原位更新自建 Sizing 与坐标系，不新建副本。用户手动修改过的控件禁止覆盖，更新失败尝试回滚并报告回滚是否失败。
- 每轮生成预览前令旧审核回执失效，避免失败后误发布旧方案。
- 改进 HTML 报告，展示每簇 Body ID、球心、半径、尺寸、已覆盖单元、预算代理和未覆盖原因。
- 仅只读生成方案；单击“审核发布 Sizing”且确认后才对现有 Meshing 增改自建 Sizing/坐标系，**不执行 GenerateMesh、不清除旧网格、不启动新 ANSYS、不触碰 Fluent**。

## 不能虚称已经完成的检查

- 既有 ACT 节点与几何关系**无法直接、完整地测量晶圆片间物理净空**。报告会把每簇写为 `manual_review_required`，发布之前须在真实 Meshing 中核对球形影响域是否跨越晶圆间隙。不能把代理量当作真实新增网格数或内存消耗。
- “自动分簇方案”不等于“网格已经优化”；发布后仍需要经用户同意重新划分并用真实最大偏度、正交质量及单元数进行对比。
- 如果原局部控制未知或不可验证、ACT 不支持原点读写、几何 Body 归属不唯一，则会安全拒绝有关候选/发布；不会编造坐标、强制覆盖手工控件。
- 当前无 ANSYS 2024 R2 / Windows 运行会话，无法完成实机功能验收；不能把离线测试当成真实 297 个单元已经成功发布。

## 针对本次工程的验证

原网格 10,055,480 单元、筛选偏度 0.90–1.00、297 个已标记。R7.5 用 **297 个合成分布单元**的 ACT 模拟回归验证：不再命中原“>64 全局拒绝”，能产生非零且受预算限制的影响域；保留实测数据时须由真实 Meshing 重新执行预览取得实际候选数量，合成模拟的分簇位置不是工程实际结果。

## 使用

1. 先保存当前 Workbench 工程，确认前一 AutoMesh 任务已结束，关闭旧 AutoMesh（不要强制结束 Workbench 或 Meshing）。
2. 解压 R7.5，运行 `AutoMesh.exe`。不要把各个版本的脚本直接覆盖到 `ProgramData`；由程序使用哈希备份并受控升级。
3. 保留当前 0.90–1.00 的真实已标记单元组；如被标记组失效，才重新按区间标记。
4. 点击“生成警告区方案”，完成后点击“查看具体范围”：逐簇检查 Body/球心/半径、覆盖单元数、拒绝原因以及片间净空。
5. 认可后点击“审核发布 Sizing”；程序回读验证并保持原网格不动。**不会自动生成网格**。
