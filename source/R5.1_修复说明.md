# AutoMesh 2024 R2 — R5.1 局部 Sizing 误拦截修复

## 截图中的错误

`RuntimeError: Actual Meshing global ElementSize outside conservative 0.35-500mm budget range: 0.0`

R5 在执行「按命名发布 Sizing」时，不必要地强制校验当前全局网格尺寸。ANSYS ACT 若返回 `0.0 [mm]`（全局自动/尚未解析），会把未确定值误当作非法显式尺寸而终止局部发布。**R5.1 不把 0 解释为实际全局尺寸，也不暗中改为参考 12 mm。**

## 修改内容

1. `publish_existing_sizing` 和 `prepare`：对于全局 `0.0 [mm]`、`Default` 等未确定状态，仍执行局部面 `面积/尺寸²` 预算检查，可发布可编辑 Sizing，且不写全局 `ElementSize`、不清除网格、不运行 `GenerateMesh`。
2. 发布结果的 `resource_preflight.global_size_status` 标记 `automatic_or_unresolved` 并附加警告，不伪称执行了全局体积预算。
3. 若是明确设置的危险全局尺寸（如 `0.05 [mm]`），继续拒绝，避免放松内存保护。
4. `generate_reviewed`：若有效全局尺寸仍无法读到，**在清除现有网格之前**阻止生成，并提示先在当前 Meshing 确认并显式设置实际全局尺寸。这一检查不会因局部发布成功而被绕过。
5. 保留 R5 模型树就绪检查、旧 Sizing 归属保护和分组逻辑，未重新设计界面；新增 R5 原 Worker SHA256 作为可升级版本。

## 使用

- 先保存现有 Workbench 工程；关闭**AutoMesh** 窗口，不必关闭当前 Workbench/Meshing。
- 解压本包到英文路径运行 `AutoMesh.exe`。如现有 worker 有用户自定义修改或任务未结束，升级保护可能拒绝覆盖，此时**不要直接删除**旧脚本，先核实日志。
- 在局部细化页刷新命名，选择一个目标组，点击「按命名发布 Sizing」。应不再因 `ElementSize=0.0` 被拦截；到 Meshing 核对真实关联与尺寸。
- **生成网格前**：如果全局网格尺寸仍显示为 0/自动且程序无法确认有效值，需在 Meshing 确认全局尺寸并显式设置用户认可的数值。AutoMesh 不会自行猜为 8/12 mm。
- **有旧网格时**，审核重划仍需确认清除。R5.1 不擅自重划、不操作 Fluent。
