# AutoMesh R7.4.1：偏度区间 ACT 类型修复

## 真实故障

当前 ANSYS 2024 R2 中执行 `mark_high_skew`（默认 0.90～1.00）时，弹出：

`TypeError: 无法将类型为 "Ansys.Core.Units.Quantity" 的对象强制转换为类型 "System.IConvertible"。`

### 根因与代码修复

R7.4 原版使用 `Quantity('0.90')` 等 Quantity 对象给 `NamedSelectionCriterion.LowerBound/UpperBound/Value` 赋值。偏度 `Skewness` 是**无量纲** Worksheet 指标；ACT 的这些属性应使用 Python 数字（自动桥接为 .NET 数值）。本版修复原生区间行和兼容双行交集分支：

- `row.LowerBound=float(low)`；`row.UpperBound=float(high)`
- 若原生 `RangeInclude` 不存在，则 `row.Value=float(low)`、`upper_row.Value=float(high)`
- 不改变质量 Worksheet 警告阈值、不重新生成网格、不改用户原有 Sizing。
- 发布包中的 EXE、内嵌 Worker 和源码来自相同修复目录。
- 接受未经修改的原 R7.4 Worker 哈希完成安全升级；人工编辑过的 Worker 不自动覆盖。

依据：Ansys Innovation Space 论坛 **Access to Worksheet Named Selection via Python console** 的示例明确区分 `criteria.IsUnitless()` 时赋数值，其他有单位的项使用 `Quantity`。ANSYS 2024 R2 官方脚本指南亦包含 Named Selection Worksheet API。

## 离线验证与实机要求

新增回归覆盖：普通 `RangeInclude`、双行 `Filter` 兼容分支、上限 1.0 和原网格不修改。测试中刻意将 `Quantity` 设为会抛出同样 TypeError 的模拟对象，确保标记时不再生成 Quantity。

离线测试/交叉编译不能替代 ANSYS 实机。请保存当前工程、关闭旧 AutoMesh、保持 Workbench/Meshing 打开，启动 R7.4.1，先执行：

1. 在质量报告页填 `0.90`～`1.00`，点击标记所选范围。
2. 确认任务 `mark_high_skew · ok`；在 Meshing 树里检查新的 `AutoMesh_Skew_900_1000_*` 命名组确实是 **Mesh Elements**，且数量大于零。
3. 再依次生成方案、查看范围；仅在有效且作用域确认后考虑发布 Sizing。
4. 此流程不会自动清除/重新生成网格或运行 Fluent。

若仍失败，请读取 `C:\ProgramData\AutoMesh2024R2\Data\last_result.json` 中 `error` 字段和对应 `job_<ID>.json`，以区分 ACT 操作符或字段兼容问题。**不应在任务未确认结束时删除锁文件或重发任务。**

注意：即使真正标记出很多高偏度单元，当前“警告区方案”仍对单次自动候选数有 64 个警告单元上限，超限时会报告需要缩小偏度区间而不是大面积生成 Sizing。本版并未实现自动重划的最优方案搜索。
