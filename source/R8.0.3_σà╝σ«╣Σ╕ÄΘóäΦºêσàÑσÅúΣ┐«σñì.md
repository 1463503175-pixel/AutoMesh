# AutoMesh R8.0.3：局部方案查看入口与旧版 Sizing 清单兼容修复

## 本次修复的问题

### 1. 「查看影响范围」按钮循环禁用

R8.0.2 的按钮启用条件同时要求 `warning_refinement_plan.html` 已存在，但该 HTML 正是点击「查看影响范围」后才生成的，因此形成循环依赖。

R8.0.3 改为以当前工程、几何指纹、预览 Job ID 和方案 ID 匹配的 `warning_preview_receipt.json` + `warning_refinement_plan.json` 作为按钮启用依据。HTML 只在用户点击查看时按当前已验证 JSON 生成。旧 HTML 文件是否存在不再影响按钮状态；历史 HTML 也不能替代当前预览回执。

### 2. 旧版本 Sizing 发布记录阻断当前方案审核

R8.0.2 Go 前端对 `warning_refinement_managed.json` 的跨工程/几何检查，比 ACT Worker 更严格：即使当前 Meshing 中已经没有任何 `AutoMesh_QR_*` 控件，旧项目遗留的发布清单仍会阻止打开候选审核页。

R8.0.3 统一 Go 前端与 ACT Worker 的判断：

- 如果历史清单属于其他工程/几何，且当前只读扫描明确证明 `Model.Mesh.Children` 中不存在 `AutoMesh_QR_*`，则将该清单视为其他工程的归档记录，不参与当前候选的已发布判断和预算累计。
- 如果当前仍存在 `AutoMesh_QR_*`，或者扫描控制清单缺失/不完整，则不猜测归属。允许打开候选列表和影响域报告，但进入只读审核模式，锁定 Sizing 发布，并明确提示原因。
- 同一工程、同一几何的有效清单继续按原逻辑核对 Candidate ID、球心、半径、尺寸和资源预算。
- 旧 Sizing、坐标系、Named Selection 和网格均不自动删除、重命名、覆盖或停用。
- 旧清单状态不明时，不显示虚假的“已有预算为 0”；明确显示预算尚未核验。

## 不变的安全边界

- 生成局部方案仍然只读，不会创建 Sizing，不会清除或重划网格。
- 查看影响范围只生成本地 HTML 报告，不向 ANSYS 发送修改命令。
- 发布仍须人工勾选、打开影响域详情、确认风险，并由 ACT Worker 对当前模型和现有控制重新核验。
- 当前模型存在无法归属的旧 `AutoMesh_QR_*` 控件时，禁止增量发布；必须先人工核对，不能为了消除提示而删除旧控制。
- 不执行 `GenerateMesh`，不操作 Fluent，不重启 Workbench/Meshing。
