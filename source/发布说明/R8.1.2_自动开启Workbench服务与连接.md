# AutoMesh R8.1.2 自动开启 Workbench 服务与连接

日期：2026-11-13。已在当前 ANSYS Workbench 2024 R2 会话验证。

## 修复结果

先打开 Workbench，再打开 AutoMesh。AM 优先验证已有脚本服务；没有可用服务时，在唯一识别的现有 Workbench 中打开命令窗口，执行一次 StartServer()，优先使用控制台返回端口，再通过 PyWorkbench 列出网格系统确认连接。不会新建 Workbench 进程或修改工程。

## 已证实原因

- 原 UI Automation 菜单路径在当前 AnsysFWW 窗口中不可见，原 helper 实测返回“命令窗口数量=0”。
- 当前菜单可通过 MSAA 原生可访问性读取准确名称；但命令窗口实际为 WindowsForms10.RICHEDIT50W，未暴露原代码要求的 Edit/ValuePattern，旧输入路径不可用。

## 修改

- assets/start_wb_server_uia.ps1：保留 UIA 优先流程，增加 MSAA 精确名称、唯一对象的菜单调用。命令窗口内只接受唯一、可写的原生 RichEdit。
- 仅在空主提示符 >>> 后写入，核对前台进程和真实焦点、移动到末端，定向发送固定 ASCII StartServer()；完整文本读回一致才定向提交一次回车。不覆盖未执行文本，不按截图或坐标控制，不自动重发不确定命令。
- 新 RichEdit 路径读取本次命令的端口输出；assets/wb_server_bootstrap.py 优先采用该端口，保留原监听端口发现流程及上层真实协议验证。
- core.go：仅增加修复前官方 helper 的精确 SHA-256 升级白名单。用户自改脚本与未结束任务仍受原保护。
- 主窗口及生命周期版本更新到 R8.1.2；其余网格逻辑沿用现有主线。

## 实机与回归证据

1. 在同一 Workbench PID 24472 中由脚本打开命令窗口并提交 StartServer()，控制台实际返回 2211。
2. 对 2211 运行 wb_cli.py list --security auto，成功返回 version=242、FFF(mesh=true) 和 Sensitivity(mesh=false)。未把其他普通监听端口当成连接成功。
3. 关闭空命令面板并收起菜单后，按 MSAA 名称依次调用“文件 → 脚本 → 打开命令窗口”成功，各入口唯一；没有再次执行 StartServer。
4. 原 AM PID 26132 已正常退出，lifecycle.jsonl 补齐 exit_requested、window_destroy、exit。安装新版后 PID 23844 自动启动并连接，last_connection.json 记录 port=2211。
5. 程序化 UI 读回：AutoMesh R8.1.2 主窗口 offscreen=false，连接成功后的动作按钮为“查看细化方案”。安装到数据目录的 helper 与本次源码逐字一致。
6. Python 全套 275 项通过（82.306 秒）；Go 顶层 223 项通过、3 项跳过、0 失败。跳过项沿用上一版：两个历史测试包缺失、一个符号链接权限不足。
7. 独立代码评审未发现阻断问题。最终 EXE 为 x64、GUI 子系统 2；SHA-256：d530640109f44381fc8822cf6ae9b050ceae6074393d741976b4efb6c5b23ad3。

AM 首次从“无服务”状态的启动链由当前会话中的实机菜单/命令执行和新版启动自动接入分别验证；为保留用户会话，没有重启 WB 或停止已验证服务做第二轮冷启动。
