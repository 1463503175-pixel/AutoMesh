# AutoMesh R7.2：已开启 StartServer() 却找不到端口的问题

## 修复的真实缺陷

1. R7.1 只扫描了本机 `10000–11200` 范围（端口框是提示值，非服务器的实际端口）。现在先通过 `netstat -ano -p tcp` 枚举 Windows 全部 TCP LISTENING 端口，并通过只读 `tasklist` 优先识别 Workbench 进程关联的监听端口。无权限读取进程名称时会继续保留全部候选端口，不将其误判为“没有服务”。
2. 原来强制 `security="insecure"`；现在只读连接时按 `mtls`、`insecure`、`wnua` 逐一尝试，成功后记录实际验证的安全模式，后续发送任务继续使用同一模式，不能在写操作阶段盲猜模式。
3. `UNIMPLEMENTED` 不再被当成证明“Workbench 未开启”，而是连接验证失败的一种诊断。程序只有能从当前服务读取到真正的 Workbench 系统清单，才报告连接成功。
4. 找到现有服务后不执行 `StartServer()`；只有所有现有候选都未验证成功、且能唯一安全识别原 Workbench 命令窗口时，才考虑自动执行。不会新建 Workbench 或使用截图坐标控制。
5. 修复版窗口明确显示 `R7.2`，不再沿用旧标题。
6. 安装器增加 R7.1/R7/R6.3.2 对应的官方脚本哈希升级兼容，个人修改的脚本仍不会被静默覆盖。

## 已验证与未验证

通过：Go 测试、Python 单元与集成模拟、Windows x64 交叉编译、脚本升级检查。`49271` 端口的模拟发现及 `UNIMPLEMENTED` 模式回退均有专项测试。

未验证：用户 Windows 上正在运行的实际 ANSYS Workbench 2024 R2 及其 `StartServer()` 实际返回端口。实际服务可能存在 RPC 版本、证书、安全模式及权限差异，不能将离线测试称为实机连接成功。

## 运行

保存 Workbench 工程，关闭旧 AutoMesh，保持原 Workbench/Meshing 打开，解压本包运行 `AutoMesh.exe`。先只测试自动连接，不要重新发布 Sizing 或重划网格。端口可保留原值；AutoMesh 会扫描其他监听端口，不再把输入值当作唯一候选。

当前 `StartServer()` 已启动时，不应再次手工输入 `StartServer()`；如果仍未连上，在 Workbench 命令窗口中检查其原先打印的端口，并保存错误信息用于进一步兼容性分析。
