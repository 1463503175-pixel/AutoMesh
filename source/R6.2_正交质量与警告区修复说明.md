# AutoMesh R6.2：正交质量诊断与警告区任务分发

## 本次修改

1. **修复 R6 的任务白名单遗漏**：`warning_refine_preview`、`warning_refine_publish` 被 Go 提交层接受；`warning_dispatch_regression_test.go` 验证 UI 调用与任务分发一致。此修改沿用已实现的 R6.1 源码。
2. **区分真实正交质量与缺失状态**：`assets/meshing_worker.py` 在有官方 `MeshMetricType.OrthogonalQuality` 时才读取 `Minimum/Maximum/Average`；检查范围 0–1。若枚举不暴露，返回 `orthogonal_quality_diagnostic.status=enum_not_exposed`；若读取异常返回 `metric_read_failed`，附原因。任何情况下都不拿 `OrthogonalAngle` 或 `1 - Skewness` 伪造正交质量。
3. **质量报告说明具体原因**：UI 质量页和 HTML 报告区分已实测、ACT 枚举不存在、ACT 取数失败，缺失时给出 Mesh/Fluent 后续核验建议。
4. **升级兼容**：加入 R6/R6.1 已发布 Worker 的 SHA-256 到允许升级清单，禁止静默覆盖用户自行修改的脚本。
5. **不改变**用户原有 Named Selection/Sizing、自动连接、生成网格、安全锁及警告单元球形影响域逻辑；正交质量读数步骤不启动 Fluent，也不执行网格生成。

## 已核实的实际限制

ANSYS 2024 R2 的 Meshing 图形界面可显示 Orthogonal Quality；当前 ACT 会话里的 `MeshMetricType` 可能没有 `OrthogonalQuality` 枚举。这是两个不同的接口层。没有该枚举时，R6.2 **仍无法直接给出正交质量实测数值**，但会明确写出真实原因。用户可在 Meshing 的 Mesh Metric 选择 Orthogonal Quality 查看统计，或在 Fluent 网格质量检查读取最终值；后者仅在用户自行选择时执行。

网格生成和警告区发布需要在用户的 Windows + ANSYS 2024 R2 中实机验收；离线模拟测试不能证明 ACT 在某台机器上暴露了某一具体属性。

## 重要验收步骤

1. 保存当前 ANSYS 工程、确认没有运行中的 AutoMesh 任务，关闭旧 AutoMesh。
2. 解压、启动 R6.2，保持原 Workbench / Meshing 会话。
3. 在「质量报告」点击「只读检查网格质量」，查看最小正交质量和详细报告中的正交质量读取状态。
4. 如果状态为「当前 ACT 枚举未开放」，先在 Meshing 界面 Mesh → Mesh Metric → Orthogonal Quality 查看数值；不要根据偏度猜测。
5. 在已标记警告单元且模型未变更时，点击「生成警告区方案」；如无错误，点击「查看具体范围」核对影响域，然后经确认发布；**不得自动重新划分网格**。
