# AutoMesh R6 整合版：发布说明与实机验收

基线：R5.3 完整源码。只操作既有 ANSYS Workbench 2024 R2 / Meshing 会话，不启动第二个 ANSYS 工程，不使用截图坐标点击，不自动进入 Fluent。

## R6 主要变更（与 R5.3 比较）

1. **任务链路两级确认**：Workbench 找到目标 Mesh 容器后写独立的 `wb_dispatch_<jobid>.json`；Meshing ACT 启动后写任务自身进度和结果，二者不能互相替代。所有标记严格匹配 UUID。
2. **超时安全恢复**：不再把等待固定 75 秒误报为“Meshing 已失败”。100 秒没有 ACT 启动确认时，以“不确定”为终止原因返回界面，保留任务锁，禁止自动重发；ACT 已执行时允许长时间计算，并独立查看阶段。若 46 分钟没有终态，仍保留锁。已经结束的任务必须有相同 UUID 的 ACT 终态才可以解锁。
3. **只读任务诊断**：质量报告页新增“检查任务状态”，查看当前任务 UUID、Workbench 路由证据、Meshing 阶段及 ACT 终态，不修改任务与模型。
4. **局部细化页显示全局参数**：当前全局 Element Size、Maximum Size、Growth Rate 的扫描值；新增“全局网格核对”，列出曲率、邻近、自适应、求解器偏好等可读取的原始属性，缺失时显示“未获取”。参考尺寸与真实 Meshing 设置明确分开，0.0 不解释成实际 0 mm。
5. **生成前审核**：将上一次扫描的全局参数与参考值显示在确认框；真正调用清网格前，ACT 仍需要重新检查全局尺寸、控制作用域、人工网格控制、资源预算与是否已经存在网格，并二次确认清除。
6. **界面控件重新布局**：修复质量报告页的按钮重叠，把其八个动作加上任务诊断排成两行；局部细化页的预算文字与底部动作错开，检查最小 1100×690 客户区的可访问性。
7. **只读质量检查优化**：质量检查和标记警告单元仅使用轻量几何指纹验证，不重复遍历每一个面的法向和边缘；几何真的变化时仍拒绝旧快照。用户在 Meshing 手动修改 Sizing 后，读取质量不再被旧控制清单无故拦截。
8. **脚本升级两阶段提交**：先校验全部 Worker、Workbench Bridge、辅助脚本的内容/哈希，再写入；存档基于 SHA-256 的旧版本备份。中途失败尝试回滚；未知修改拒绝覆盖；未确认结束的任务禁止升级。增加 R5.2/R5.3 Worker 和 R5.1–R5.3 Bridge 的精确哈希。
9. **保留原有能力**：自动探测端口和安全尝试 StartServer、Named Selection、Sizing.Location、重复发布与停用、8 mm 分组持久化、已有网格审核重划、Worksheet 质量标记、警告区 SOI 局部二次细化、存储路径迁移、报告导出和 32 GB 保守资源预检。

## 验证结论（离线）

- Windows x64 GUI EXE：交叉编译成功，PE32+ 有效。
- Go：`go test -count=1 ./...` 通过；`go test -race ./...` 通过；`go vet ./...` 通过。
- Python：`pytest` **182 passed, 2 subtests passed**；包括旧版测试和新增任务回执、手工 Sizing 后只读检查、界面几何位置、升级拒绝混装等。
- 上述全部属于模拟或源码测试，并不意味着在真实 ANSYS 2024 R2 内验证成功；当前环境没有你的 Windows/ANSYS 运行会话。

## 安装与现场验证顺序

1. 先在 Workbench 保存工程；确认之前的 AutoMesh/Meshing 任务已经完成。**不能仅因没看到进度就直接清除旧任务锁**。
2. 关闭旧版 AutoMesh，保持原 Workbench / Meshing 已打开。将整个 ZIP 解压到英文路径，例如 `D:\Tools\AutoMeshR6`，运行根目录 `AutoMesh.exe`。不得叠加旧热修复补丁。
3. 打开“连接工程”，端口可选“自动”；软件先复用已运行的 StartServer 和历史端口，仅在控件唯一且可验证时自动执行 StartServer()。失败时不新开 Workbench，按提示处理。
4. 先执行只读扫描：确认命名列表完整、单位正确、分组勾选/取消后切换页面和重启可恢复。查看“全局网格核对”，务必区分实时 Meshing 当前值与上一次扫描记录。
5. 从一个现有 Named Selection 测试发布 Sizing，回到 Meshing 检查作用面、数值、重复发布行为。测试取消已发布组及再启用时不会误操作人工控件。
6. **仅在保存工程、有网格备份、且全局尺寸等必要信息均可验证后**点击“审核后生成网格”。任务状态先出现 Workbench 确认，再出现 ACT 阶段；只有 ACT 报告 GenerateMesh 已执行才可称为真正生成。
7. 网格生成后点击“只读检查网格质量”、标记警告、生成警告区方案并审核影响域。警告细化只创建局部 Sizing，**不会自动重新生成网格**。重新生成后要重测官方质量分布、最小正交质量和必要的 Fluent 质量指标。
8. 如连续等待且 Meshing 无动作，打开“质量报告 → 检查任务状态”，记录 UUID、最后已证实的阶段以及 `last_workbench_error.log` 和对应 JSON；不要重复点击发布。

## 仍需真实 ANSYS 验证 / 软件能力边界

- Workbench 2024 R2 的 `SendCommand()` 在你的系统可能被排队、隐藏编辑器或其他机制阻塞；路由回执只证明 Workbench 找到了目标 Mesh 容器，**不证明** Meshing 真正开始执行。
- Windows 控件自动化能否安全调用 `StartServer()` 取决于实际命令窗口是否可被唯一识别；失败时停下，不使用鼠标坐标盲点。
- 质量报告无法从当前 ACT 接口读到的指标必须保留“未获取”，不允许估算成真实正交质量；正式 Fluent 适用性仍要在 Fluent Mesh Check 和对比分析中验证。
- 每个警告单元不是永久几何实体：二次细化前需把单元坐标映射到真实几何体；重划后 ID 失效。细化不保证偏度下降；最多生成 6 个 SOI 候选以适配内存限制。
- ANSYS Mechanical Meshing 的主要几何与网格计算是 CPU 工作；RAM 负责存储模型，显卡不能直接替代原生 Meshing 的 CPU 计算。CPU 峰值与 ANSYS 生成耗时需要在你的设备上测量。
- 本版本没有在本环境完成实际 Windows GUI/DPI、StartServer、Workbench → Meshing、重划网格的端到端验收。仅在完成以上现场验收后才能将其认定为你设备上的稳定最终版。
