# AutoMesh R8.0.4：连续优化与历史 Sizing 接管

## 1. 本次修复的问题

R8.0.3 的警告区发布清单把 `candidate_id` 同时用于标识候选和历史 Sizing。候选 ID 包含当前网格的单元 ID；用户重新生成网格后，单元 ID 会变化，旧候选 ID 因而不再出现在新方案中。R8.0.3 将这种正常的跨网格轮次变化误判为历史 Sizing 无法匹配，导致候选页进入只读模式。

R8.0.4 将两种身份分开：

- **历史 Sizing 身份**：当前 ACT 模型树中的真实 Sizing 对象、对象 ID、Body 作用域、坐标系对象 ID、球心、半径、目标尺寸及启用状态。
- **本轮候选身份**：当前网格中标记的单元、分簇结果和本轮 `candidate_id`。

旧网格的候选 ID 不再是继续优化的前置条件。

## 2. 历史 Sizing 接管规则

当共享发布清单缺失或属于其他工程/几何，但当前模型仍有 `AutoMesh_QR_*` 控件时，ACT 只在以下条件全部满足后才从当前模型重建接管记录：

1. 对象确实是 `SphereOfInfluence` 类型 Sizing；
2. Sizing 未被 Suppress；
3. 作用域可读取且恰好对应一个当前几何 Body；
4. Body ID 属于当前扫描几何；
5. Sizing 与 `AutoMesh_QR_CS_*` 坐标系按名称和对象 ID 唯一配对；
6. Element Size、Sphere Radius 都能按明确单位换算为 mm；
7. 球心坐标可读取且为有限数值；
8. 尺寸、半径位于程序安全核验范围内；
9. 不存在重复身份、共用球心坐标系或未配对的 AutoMesh 球心坐标系。

接管只建立本地审计清单，不修改现有 Sizing，不移动球心，不改变尺寸，不删除或 Suppress 控件。

若对象被人工改名、停用、修改作用域、修改尺寸/球心，或属性无法读取，程序仍会停止发布并说明具体原因；不会强行解除只读锁。

## 3. 跨网格轮次发布

- 同一候选 ID 若仍存在于当前方案，必须核对 Body、球心、半径和尺寸；任何不一致均拒绝重复发布。
- 旧候选 ID 若不再出现在当前方案，按“历史网格轮次”保留，不再要求它出现在新网格候选列表中。
- 历史 Sizing 继续参加累计资源预算和球形影响域近重合检查。
- 近乎重合的球形影响域禁止重复发布；普通部分相交区域仍需用户打开详情、核对晶圆片间净空并人工确认。
- 新发布只追加本轮已勾选的候选。未勾选候选保留；本轮已发布候选不会再次发布。
- 发布记录升级为 schema 3，按 `plan_id` 保存网格轮次、网格单元数、候选 ID、批次及发布时间。旧轮次记录保留。
- `remaining_count` 只统计当前方案中尚未发布的候选，不再用历史 Sizing 总数减当前候选数。

## 4. 实时读取与前端显示

此前 `warning_refine_preview` 等只读任务复用上一次完整几何扫描文件，其中的 Sizing 控件清单可能早于用户重新生成的网格和第一轮 Sizing 发布。

R8.0.4 在几何指纹仍匹配时，额外刷新当前 ACT 模型树中的：

- 所有现有 Mesh 控件；
- AutoMesh 警告区 Sizing 的对象 ID、Body、类型、启用状态、尺寸、球心、半径；
- 对应坐标系名称和对象 ID；
- 当前网格单元数、节点数和全局尺寸摘要。

该刷新不重新遍历全部几何面，不清网格，不执行 GenerateMesh。刷新后的清单写回本地只读快照，Go 前端在任务完成后重新读取。

候选审核页增加：

- 当前模型历史 Sizing 数量；
- 已有控制累计预算；
- 候选与历史影响球的相交/近重合状态；
- 影响域报告中的历史 Sizing 清单、对象 ID、Body、球心、半径、尺寸和预算代理。

## 5. 资源与操作边界

- 继续沿用累计预算上限 `120000`（仅为安全代理，不是实际新增单元数）。
- 每个 ACT 发布批次最多 6 个 Sizing；可多次勾选发布，未选候选继续保留。
- 发布前仍由 ACT 重新读取所有历史 Sizing，并对当前候选进行几何、作用域、预算和重复球检查。
- 不自动执行 `GenerateMesh`。
- 不调用 `Clear Generated Data`。
- 不删除、不覆盖、不 Suppress 任何历史 Sizing 或坐标系。
- 用户在 Meshing 手动生成新网格后，必须重新标记当前偏度区间、重新生成局部方案，再审核本轮候选；旧候选选择回执不能跨网格复用。

## 6. 推荐的连续优化流程

1. 第一轮：标记偏度区间 → 生成方案 → 打开影响域报告 → 勾选确认 → 发布 Sizing。
2. 用户在 Meshing 中检查已发布的 Sizing，保存工程，并按需要手动生成新网格。
3. 新网格生成后，重新标记当前 `0.90–1.00`（或用户指定）偏度区间。
4. 重新生成局部方案。ACT 在只读阶段刷新当前历史 Sizing 清单并计算累计预算。
5. 打开候选审核列表。历史 Sizing 保留；本轮新候选按当前可核验偏度从高到低显示。
6. 对近重合候选取消勾选；对部分相交候选打开影响域详情，核对片间净空后再确认。
7. 发布所选候选。程序只追加本轮新 Sizing，不重建第一轮控件、不重划网格。
8. 如再次手动重划，重复第 3–7 步，直到达到质量目标。

## 7. 测试与验收边界

离线测试覆盖：

- 同一网格轮次分批发布；
- 第一轮发布后更换网格单元 ID，再次发布新候选；
- 第一轮 Sizing 与坐标系对象保持原样；
- 旧清单工程身份过期时，从当前 ACT 控件精确接管；
- 人工修改 Sizing、停用 Sizing、作用域不唯一、坐标系不匹配和近重合球体仍被拒绝；
- 历史预算累计；
- 同一候选 ID 的几何变化仍被拒绝；
- 本轮剩余候选数量按本轮 ID 统计。

测试结果：Python 218 项通过；Go 全部测试通过；Windows x64 EXE 构建成功。

**限制：** 这些结果来自离线测试与 ACT 模拟环境，不等同于已在用户的 ANSYS 2024 R2 实际会话完成端到端验收。首次使用仍应先核验历史 Sizing 清单和候选影响域，不要直接批量发布。
